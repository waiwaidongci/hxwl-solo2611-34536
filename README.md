# 折页月刊｜订阅报价实验

`hxwl-solo2611-3` · 小样本 A/B 实验

结账服务按读者随机展示季度订阅报价。A 为每季 ¥39，B 为首季 ¥29、续订恢复 ¥39。增长分析师把随机分流、首单支付和退款合在同一张台账，在预先约定的复盘日判断 B 能否向更多读者开放。

## 模拟客户与工作流

折页月刊读者营收组（8 人，约 1.2 万名付费读者）

- 营销周报只汇总付款订单，结账后离开的读者常漏算。
- 财务退款表更新较晚，未满七天的订单容易被当成无退款。
- 报价会只报转化涨幅，发行和客服缺少同一份放量依据。

发行运营根据预设门槛决定是否让 B 覆盖 25% 的全站合格结账流量。护栏触发时恢复 A，由客服质检核对退款原因。样本或观察期不足时维持当前试点范围，待数据到齐再复盘。

## 业务模块

- 随机结账台账
- 实验阈值与复算
- 转化证据与放量决策
- 发行与客服收件箱

## 计算口径

结账服务按读者随机分流，分析按原分组统计所有入组读者。以本次结账支付/入组计算转化，退款订单仍算转化。转化 2×2 表使用双侧 Fisher 精确检验，按固定边际累加概率不大于观测表的所有表。以北京时间结账日为 D0，七天退款窗口覆盖 D0 至 D+7 日终。最小提升门槛按观测转化差判断。各组只用完整观察满七天的支付计算成熟退款率，B 的护栏另看单侧 95% Clopper–Pearson 精确上界。已知窗口内退款占全部 B 支付可用于提前触发停测。复盘日和阈值应在试验前确定，历史回看用于核对数据，反复查看 p 值会改变试验的错误率。首季结果只覆盖这次报价试验，续订率和单位收入仍需跟踪。

样例输入为 `折页月刊_季度报价结账_20261124.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 24 日 09:00 增长分析师导入《折页月刊_季度报价结账_20261124.csv》，覆盖 11 月 10 日至 16 日的 72 位随机入组读者。
2. 09:15 核对 A、B 各 36 位读者，首单支付分别为 10 笔和 24 笔。
3. 09:30 在随机结账台账核对 A 有 2 笔七天内退款，B 有 1 笔在窗口结束后退款。
4. 10:00 按 11 月 23 日终的预定快照运行，门槛为每组至少 30 人、转化至少提升 10 个百分点和 B 七天退款率上限 15%。
5. 10:20 在决策页核对转化差为 38.89 个百分点，B 的 24 笔支付均成熟，七天内退款为 0 笔。
6. 11:00 将放量结论发给发行运营组和订阅客服质检组，保留实验参数和退款分母。
7. 14:30 发行运营安排 B 覆盖 25% 的全站合格结账流量，客服复查那笔窗口外退款并归档。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18312`，API `http://127.0.0.1:19312`，数据库宿主端口 `17812`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
